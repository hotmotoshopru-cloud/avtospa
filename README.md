# АвтоSPA WordPress theme

Современная тема для сайта автомойки и шиномонтажа АвтоSPA в Москве.

## Проверка перед сборкой

Тема сделана как классическая WordPress-тема: `style.css` и `index.php` находятся в корне, а стандартные шаблоны подключаются через WordPress Template Hierarchy.

## Что показал предоставленный error_log

Ошибки в логе относятся в основном к существующему сайту, его плагинам и серверному окружению, а не к будущей теме:

- **WP Statistics:** `Unknown column 'first_page' in 'field list'` — схема таблицы базы данных не соответствует версии/коду плагина.
- **WP Stats Manager:** хостинг запрещает пользователю БД выполнять `CREATE VIEW`.
- **WordPress HTTP/Requests:** отсутствуют классы `WpOrg\\Requests\\Cookie\\Jar` / `Requests_Cookie_Jar` — это проблема файлов/совместимости ядра WordPress или окружения.
- **All in One SEO Pack:** присутствует в стеке вызовов, поэтому тема не должна дублировать его SEO-мета-теги.
- **Wordfence:** cron-событие не смогло сохраниться.
- **ModSecurity:** WAF блокирует запросы к REST API пользователей; это защитное правило сервера.
- **Autoindex:** попытки открыть служебные каталоги блокируются сервером, что само по себе не является ошибкой темы.

Тема не использует WP Statistics, WP Stats Manager, Wordfence или другие плагины напрямую и не должна создавать перечисленные ошибки.

## Что исправлено в теме

- Корректный `style.css` с WordPress theme header.
- `index.php` в корне темы.
- Стандартные `header.php`, `footer.php`, `page.php`, `single.php`, `archive.php`, `search.php`, `404.php`, `comments.php`.
- Корректное подключение CSS/JS через `wp_enqueue_style()` и `wp_enqueue_script()`.
- Проверка наличия популярных SEO-плагинов перед выводом резервного description, чтобы не создавать дубли.
- Schema.org без непроверенного специализированного типа.
- Экранирование пользовательских настроек и URL.
- Доступное мобильное меню.
- Никаких непроверенных дополнительных услуг на главной.
- Старое обозначение режима работы полностью удалено из темы.

## Перед установкой

1. Сделать резервную копию сайта и базы данных.
2. Проверить PHP и обновить сервер до актуальной поддерживаемой версии. WordPress рекомендует PHP 8.3+; PHP 7.4 является только legacy-совместимостью.
3. Обновить WordPress и плагины.
4. Для WP Statistics и WP Stats Manager выполнить штатное обновление/восстановление таблиц через сами плагины. Не менять базу вручную без резервной копии.
5. Проверить cron и права базы данных на хостинге.
6. После установки проверить главную, мобильную версию, телефон, SEO-плагин, sitemap и Schema.org.
